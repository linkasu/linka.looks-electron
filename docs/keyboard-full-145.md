## Сравнение с OptiKey Chat

Источники, прочитанные 2026-11-03:

- <https://optikey.org/applications/optikey-chat>
- <https://optikey.org/media/pages/applications/optikey-chat/2544573451-1705172910/keyboard_alpha_speech_only.png>

Страница описывает full-screen QWERTY и эквиваленты других языков, предиктор и речь.
На изображении — отдельная полоса предсказаний, текст с курсором, три постоянных
ряда букв, крупные speech/sleep, удаление символа/слова и пробел. Стрелки полосы
предсказаний не используются здесь для листания букв.

Перенесён принцип компоновки, **не активы и не чёрная тема OptiKey**. Использованы
существующие LINKa EyeButton, общая пауза/dwell, светлая тема и бирюзовый primary.
Курсор открывает отдельную навигацию; цифры и знаки вынесены отдельно: ещё один
выбор взглядом предпочтительнее постоянного уменьшения всех букв ради редких действий.
Swipe, словари, новые настройки и пользовательский выбор режима в production не добавлялись.

## Три варианта

| Вариант               | Компоновка                                                                        | Компромисс                                           |
| --------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------- |
| **A — полная ширина** | Команды сверху, текст, три подсказки, режимы, три ряда букв, редактирование снизу | Наибольшая ширина букв; предварительная рекомендация |
| B — команды справа    | Постоянная вертикальная полоса pause/speech/undo/clear                            | Выше цели команд, но уже буквы                       |
| C — подсказки слева   | Три высоких подсказки рядом с клавиатурой; текст сверху                           | Подсказки крупнее, но меньше ширина букв             |

Это варианты для выбора владельцем, не три production-настройки. В production
собирается только A; переключатель и альтернативы выбираются только в dev через
`?variant=A|B|C`. Отдельная demo HTML-страница не входит в build inputs.

## Матрица поведения и сохранения

| Действие/состояние        | Контракт                                                                                      |
| ------------------------- | --------------------------------------------------------------------------------------------- |
| RU, буквы                 | Одновременно все 33: `ёйцукенгшщзхъ` / `фывапролджэ` / `ячсмитьбю`                            |
| EN, буквы                 | Одновременно все 26: `qwertyuiop` / `asdfghjkl` / `zxcvbnm`; ручной ввод                      |
| Регистр                   | Все ряды переключаются вместе, без смены экрана                                               |
| Предиктор                 | Три постоянные ячейки; пустые недоступны, буквы не двигаются и не исчезают                    |
| RU-запрос в работе/ошибка | Ручные буквы доступны; старые результаты отменяются прежним контрактом                        |
| EN                        | Запросы RU не отправляются, показано «EN · ручной ввод»; не выдуманы EN-предсказания          |
| Цифры/знаки               | Отдельные полные экраны, остаются выбранными после ввода и смены языка                        |
| Курсор                    | Вместо букв шесть крупных команд навигации; текст сохраняется; «Буквы» возвращает             |
| Убрать слово              | Предыдущее слово с хвостовыми пробелами, по прежней whitespace-семантике навигации; один Undo |
| Говорить/Стоп             | Одна цель меняется на «Стоп»; остановка не считается ошибкой речи; текст не очищается         |
| Пауза/возобновить         | Прежний общий EyeButton/GazePauseButton; черновик, язык и экран не сбрасываются               |
| Переключить A/B/C         | Только геометрия, без изменения черновика, языка и истории                                    |
| Закрыть/вернуться         | Прежняя запись `eyeTypingDraftV1`, text+code-point caret атомарно; язык/экран/Undo эфемерны   |
| Demo в браузере           | Только память вкладки, синтетические подсказки, без реальной речи/трекера/IPC/записи на диск  |

Новых writers, миграций, блокировок, счётчиков и фоновых очередей нет. Main остаётся
единственным writer реального черновика. Старый бинарник игнорирует прежний ключ;
rollback не меняет его формат. Отмена предиктора не объединяется с ошибкой.

## Запуск прототипа

Node 22.22.2, имеющиеся зависимости:

```sh
npm run prototype:keyboard
```

Открыть <http://127.0.0.1:5193/typing-prototype.html?variant=A>, затем B/C стрелками
панели или параметром URL. Сервер слушает только loopback и откажет при занятом порте.
Вкладка прямо обозначена как DEMO, не рабочий черновик. Кнопки вводят текст в память;
«Озвучить всё»/«Стоп» демонстрируют состояние, не воспроизводят звук. Перезагрузка
сбрасывает demo. После просмотра закрыть вкладку и остановить сервер Ctrl+C.

## Проверки

До исправления новые unit-тесты выявили 5 ожидаемых падений: старое листание,
отсутствие QWERTY-рядов/удаления слова и нестабильная полоса предсказаний.
После основной правки focused model/view: **23 passed**.

Проверены A/B/C на 800×600, 1024×768, 1280×720, 1366×768, 1920×1080 в CSS pixels,
для RU и EN. Проверки измеряют присутствие/порядок букв, попадание целей в viewport,
отсутствие обрезания надписей, стабильность геометрии при появлении подсказок,
редактирование, Undo, режимы, паузу и speech/stop. Это **не порог точности взгляда**:
нужны реальные экран, масштаб ОС, расстояние, калибровка и пользователь.

Например, в A минимальные RU-цели на 800×600 — **54.77×65.33 CSS px**,
на 1366×768 — **98.30×121.33**; в B/C на 800×600 ширина RU уменьшается до

по сохранению ширины, а не по выдуманному порогу. На маленьком экране даже A может
оказаться неудобен конкретному пользователю — требуется настоящая проба взглядом.

реальное произношение или калибровку. Built-file Electron проверен с tiny-моделью,
но **не называется packaged**. Полная RU-модель, её latency, Windows, портретная
ориентация и масштаб ОС кроме текущего окружения не проверялись.

Первый браузерный запуск обнаружил отсутствующий Playwright headless shell;
использован уже установленный Chrome (`channel: chrome`), без скачивания браузера.

## Безопасная проба на «мини»

1. Сначала уточнить, какое устройство называется «мини», его ОС, разрешение и масштаб.
   Ни удалённый адрес, ни устройство не угадывались; подключений и запусков на нём не было.
2. Для первого сравнения — только loopback demo выше, локальные файлы этого worktree,
   без установки поверх рабочей LINKa, production-драфтов, реального предиктора или речи.
3. Выбрать A/B/C по парным RU/EN-скриншотам и реальной пробе. Если требуется управление
   взглядом, browser demo его не квалифицирует: нужен отдельный согласованный Electron-прогон
   с временными userData/home, без обновления установленной программы и без ослабления защиты.
4. До такого прогона устранить **унаследованные blockers**: неполное dependency tree
   packaged Electron (conf/usb/semver), квалификация production RU-модели и два baseline
   security-test failures, зафиксированные предыдущим writer. Этот прототип их не исправляет.
5. Сначала убедиться, что возврат к текущей программе возможен, затем ручные RU/EN ввод,
   слово/Undo, курсор, пауза, говорить/стоп, длинный текст и фактическая калибровка.
   Не меняются автозапуск, постоянные разрешения, учётные данные и защитные политики.

Commit/push, PR, деплой и релиз не выполнялись. Для публикации и запуска на устройстве
нужно отдельное явное поручение; текущая доставка прототипа не означает завершение issue145.
